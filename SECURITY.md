# Security Policy

## Supported Versions

Security updates and patches are actively provided for the following versions:

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |
| < 0.1.0 | :x:                |

## Reporting a Vulnerability

The MAIVW Protocol team takes security issues seriously. If you discover a vulnerability or potential security risk, please follow responsible disclosure guidelines.

**DO NOT report security vulnerabilities through public GitHub issues, discussions, or pull requests.**

### Preferred Reporting Method

1. **GitHub Private Vulnerability Reporting**:
   Navigate to the **Security** tab of this repository, select **Advisories**, and click **Report a vulnerability** (or use [this direct link](https://github.com/SilvioSLN/maivw-protocol/security/advisories/new)).

2. **Security Contact**:
   If Private Vulnerability Reporting is unavailable, send an encrypted or direct email to:
   - **Email**: `security@maivw.com` (or maintainer contact: `silviosln@gmail.com`)
   - **Subject**: `[SECURITY VULNERABILITY] MAIVW Protocol - <brief summary>`

### What to Include in Your Report

To help us triage and resolve the issue quickly, please provide:
- A clear description of the vulnerability and its potential impact.
- The affected component(s) (`gateway`, `contracts`, `solana`, `p2p`, `auth`, `storage`, etc.).
- Step-by-step reproduction instructions or a minimal Proof of Concept (PoC).
- Any suggested mitigations or patches (if available).

### Response Timeline

- **Acknowledgment**: Within 48 hours of receiving your report.
- **Assessment**: We will investigate and confirm the issue within 5 business days.
- **Fix & Advisory**: We will develop and release a security patch before publishing any public CVE or advisory.

### Safe Harbor

Security research conducted in good faith according to this policy is considered authorized. We will not initiate legal action against researchers who:
- Give us reasonable time to remediate before public disclosure.
- Do not access, modify, or delete user or tenant data without explicit authorization.
- Do not disrupt services or execute Denial of Service (DoS) attacks against live deployments.
